## 2. Problem Solved by the Notebook

The notebook solves the following task:

Given a pulsar on a circular orbit at fixed `(r_s, theta_s)`, and an observer at `(r_o, theta_o, phi_o)`, compute the primary image at a fixed grid of orbital phases

```python
psi = 2*pi*k/n_pts
phi_eff = phi_o - psi
```

For each `psi`, the notebook finds an image whose final ray position satisfies

```python
theta_f = theta_o
phi_f = phi_eff   modulo 2*pi
```

and selects the primary image, operationally identified as the valid image with the smallest `n_half`.

## 4. Automatic Primary Initialization at `psi = 0`

## 5. Continuation in `(lambda, q)`

After initialization, the notebook continues the image around the circular orbit using `(lambda, q)` as the root variables.

The root residual is:

```python
residual_lamq = [
    ray.theta_f - cfg.theta_o,
    sin((ray.phi_f - phi_eff)/2),
]
```

The second residual uses `sin((delta_phi)/2)` so that the azimuthal matching is periodic and insensitive to adding multiples of `2*pi`.

For each new phase, the solver starts from the previous solution:

```python
x0 = [previous_lam, previous_q]
```

It first tries the previous signs `(nu_r, nu_theta)`. If that fails or if another branch gives a better valid root, it tries sign alternatives generated by:

```python
branch_trials(nu_r, nu_theta)
```

The successful root with the smallest `n_half` among the tried branches is selected.

## 6. Local Perturbation Before Sweep Fallback

If the direct `(lambda, q)` continuation fails, or if `n_half` changes too much relative to the previous point, the notebook first tries cheap local retries before using the expensive all-branch sweep.

The local guesses are generated from the previous seed using:

```python
local_perturb_scales
local_perturb_patterns
```

For example, for a scale `s`,

```python
delta_lam = s * max(abs(lam0), 1)
delta_q   = s * max(abs(q0), 1)
```

The default patterns try positive and negative directions in `lambda`, in `q`, and diagonal combinations. This often recovers the correct root when the previous seed is close but the nonlinear solve is sensitive.

## 7. Primary-Image Guard Using `n_half`

The notebook uses `max_nhalf_jump` to guard against accidentally moving from the current primary-image branch to a discontinuous image branch.

The direct root is rejected if:

```python
abs(ray.n_half - seed["n_half"]) > max_nhalf_jump
```

The same absolute-jump check is also applied after local perturbation and after sweep fallback. This post-sweep check is important because an all-branch sweep can find valid images that are not continuous with the previous primary branch.

If the sweep result itself violates the guard, the phase point is marked as failed rather than silently accepting a likely discontinuous image.

One diagnostic exception is deliberately kept in the current notebook: if a direct `(lambda, q)` root exists but triggers the `n_half` guard, and the subsequent all-branch sweep finds no replacement image, the notebook keeps the direct root with method

```python
"root_lamq_guarded"
```

This row is still marked as `success=True`, but its method and `fallback_reason` indicate that it should be inspected as a guarded diagnostic candidate rather than treated as an unproblematic continuation point. As a caveat, it also becomes the seed for the next continuation step, so this exceptional path can propagate a possible branch jump.

## 8. All-Branch `(r_c, log10|d|)` Sweep Fallback

When continuation and local perturbation do not produce a trustworthy primary image, the notebook falls back to:


This is built on KerrP2P's native `(r_c, d)` sweep, but adds orchestration around it:

1. Construct a uniform grid:

```python
rc_list  = linspace(rc_min, rc_max, rc_size)
lgd_list = linspace(log_abs_d_min, log_abs_d_max, d_size)
```

2. Run all eight sign branches:

```python

```

3. Collect built-in KerrP2P sweep results.

4. Add extra Python-side refinement candidates.

5. Deduplicate images in `(lambda, q)`.

6. Select the smallest-`n_half` candidate.

The selected ray is converted back into `(lambda, q)` and used as the new continuation seed.

## 9. Python-Side Sweep Refinement

The notebook adds a refinement layer that does not exist in pure KerrP2P.

KerrP2P's built-in `sweep_rc_d_Float64` detects grid cells where the `theta` and `phi` residual contours cross and polishes only a limited number of candidates controlled by `cutoff`.

The notebook additionally uses the diagnostic arrays returned by the sweep:

- `theta_roots_closest`
- `phi_roots`
- `theta_roots`

It selects up to:

```python
sweep_refine_max_candidates
```

from these arrays and applies SciPy root polishing in `(r_c, log10|d|)`:

```python
optimize.root(
    lambda x: residual_rcd(x, cfg, phi_eff, nu_r, nu_theta, d_sign),
    x0,
    method="hybr",
    tol=tol_sweep_refine,
)
```

Here `tol_sweep_refine` controls the SciPy root solver's iteration tolerance. The final acceptance of a refined candidate is checked by the residual norm condition

```python
resid_norm < max(1e-6, 10 * tol_sweep)
```

so `tol_sweep` still controls the effective acceptance scale for these refined sweep candidates.

This refinement layer is useful when the built-in sweep detects useful contour information but does not return the primary image as a polished result.

The notebook reports these as two sources:

- `built-in`: images returned directly by KerrP2P's sweep
- `refined_new`: branch-level log count of additional images recovered by the Python-side refinement
- `scipy_refined`: row-level `sweep_source` value used when the selected image comes from the Python-side refinement

## 10. `tol_sweep` and `cutoff`

These are lower-level controls passed to KerrP2P's built-in sweep.

From the KerrP2P C++ implementation:

1. `sweep_rc_d` evaluates the ray residuals on the `(r_c, log10|d|)` grid.

2. It identifies grid cells where the `theta` residual and `phi` residual change sign.

3. It pairs nearby `theta` and `phi` contour cells and sorts them by grid distance.

4. It only runs Broyden polishing on the first `cutoff` candidates.

5. A polished candidate is accepted only if the final residual norm is below `tol_sweep`.

6. The same `tol_sweep` is also used to remove duplicate built-in roots in `(r_c, log10|d|)`.

Thus:

- increasing `cutoff` can recover images farther down the candidate ordering, but costs more time;
- decreasing `tol_sweep` demands more accurate built-in roots, but may reject candidates that are good enough for continuation;
- increasing `rc_size` and `d_size` changes the grid itself, while increasing `cutoff` changes how many detected candidates are polished.

## 11. Exception Handling Around Invalid Trial Rays

The notebook catches exceptions from KerrP2P calls that can occur for invalid trial parameters, especially near elliptic-integral domain boundaries.

This protection is applied to:

- `calc_ray_lamq`
- `ray_from_rcd`
- each branch call to `sweep_rc_d_Float64`

If a trial ray fails, the notebook treats it as invalid:

- root residuals return a large value;
- invalid refinement candidates are skipped;
- invalid built-in sweep branches are skipped.

This prevents a single bad trial point from stopping the entire orbit solve.
